1. What it does

rserial lets you open a serial port, watch incoming data live (as text or hex), and send data back — all from a keyboard-driven terminal UI. The workflow is three screens:

Select Port  →  Configure (baud, bits, parity, stop)  →  Monitor (read / send)

7. REST API

Other programs can drive the serial connection over a small localhost-only HTTP API. It is off by default — enable it at launch:

# Default port 8791
rserial --api

# Custom port
rserial --api-port 9000

The server binds to 127.0.0.1 only (same-machine callers, no auth).

MethodPathAction
GET/api/statusJSON: {connected, port, reconnect_in_secs}
POST/api/disconnectDisconnect the port now
POST/api/reconnectReconnect to the last port/config now
POST/api/cycle?secs=30Disconnect now, auto-reconnect after N seconds (default 30)

Example: free the port for another tool for 30 s

# flasher wants exclusive access to /dev/ttyACM0 for ~30s
curl -X POST 'http://127.0.0.1:8791/api/cycle?secs=30'
#  ... run your flasher ...
# rserial auto-reconnects when the timer elapses; poll status to confirm:
curl http://127.0.0.1:8791/api/status

8. How it works

No async runtime — serial I/O runs on plain OS threads:

  • Reader thread — reads from the port with a 100 ms timeout and pushes chunks over a bounded sync_channel(256).
  • Writer thread — receives Vec<u8> from the UI and writes to a cloned port handle.
  • Stop signal — an Arc<AtomicBool> checked each loop iteration for a clean disconnect.
  • Main loop — redraws at ~60 fps (16 ms poll interval); also drains API commands and services the auto-reconnect timer each tick.
  • API thread (with --api) — a blocking tiny_http server that only issues commands over an mpsc channel and reads a shared status snapshot; it never touches serial state directly.

Tech stack: Rust (edition 2024), ratatui + crossterm (TUI), serialport (I/O), arboard (clipboard), tiny_http (REST API).
